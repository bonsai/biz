# 『思想家とAI』動画制作計画

## 1. 目的

既存の思想家とAIの原稿31話を、再現可能な制作パイプラインで動画化する。まず1本で制作手順と品質基準を固め、その後に残りの話へ横展開する。

## 2. 基本方針

- 原稿とエピソード情報を正本とし、動画用に内容を勝手に変えない。
- パイロットは第1話「マルクスとAI」とする。
- TTSはVOICEVOX Engineを使用する。
- 画像はGeminiで用意し、1話につき1枚のPNGを受け取る。
- 動画生成はFFmpegで行い、GitHub Actionsから手動実行できるようにする。
- 1話ごとの手作業を減らし、共通テンプレートと自動生成を優先する。
- 画面は情報を読みやすくし、派手な演出より思想の理解を優先する。
- 思想家の肖像に依存せず、概念図・タイポグラフィ・抽象的な図形を基本素材にする。
- 公開先や声の種類など、未決定事項は試作後に判断する。

## 3. 制作パイプライン

1. **原稿の取り込み** — `episodes.jsonl` から話数、タイトル、トピック、文字数、予想時間を取得する。
2. **読み上げ用原稿の整形** — 見出し・記号・固有名詞の読みを確認し、内容を保ったままTTS向けに整える。
3. **音声生成** — VOICEVOX EngineでWAVを生成し、発音・間・速度・音量を確認する。
4. **字幕生成** — 原稿と音声に基づき字幕を作成し、長すぎる行や表示時間を調整する。
5. **映像生成** — 共通テンプレートにタイトル、問い、キーワード、概念図、字幕を配置する。
6. **書き出し** — FFmpegで16:9・1920×1080のMP4を生成し、字幕を焼き込む。
7. **品質評価** — 内容、音声、字幕、映像、権利、生成失敗、制作時間をチェックする。
8. **公開・記録** — 公開先が決まったら投稿し、動画URLと評価結果をメタデータに記録する。
9. **改善** — 視聴者の反応と制作コストを見て、テンプレートと次回制作を改善する。

## 4. 1話の構成テンプレート

1. **冒頭フック** — 現代のAIに関する短い問い
2. **思想家の視点** — その思想家の中心概念を紹介
3. **AIへの接続** — 概念をAIの具体的な問題に適用
4. **具体例・図解** — 抽象論を1つの例で説明
5. **問い直し** — 単純な正解に回収せず、別の視点を示す
6. **締め** — 視聴者が考え続けられる一文
7. **エンドカード** — シリーズ名と次の話への導線

原稿に存在しない主張や引用を、演出の都合で追加しない。追加の調査が必要な箇所は公開前に確認する。

## 5. ビジュアル設計

- 画面比率：16:9を基本とする。
- 基本画面：タイトル、ナレーション字幕、キーワード、簡単な概念図。
- 字幕：スマートフォンでも読める大きさ、短い行、十分なコントラスト。
- 動き：キーワードの出現、概念同士の接続、場面転換など意味のある動きに限定する。
- 音：ナレーションを主役にし、BGM・効果音は声を妨げない範囲にする。
- 素材：ライセンスと出典を記録する。権利関係が不明な画像・音源は使わない。

## 6. パイロット：第1話「マルクスとAI」

### 先に検証すること

- 日本語TTSが固有名詞や哲学用語を正しく読めるか
- 字幕と音声の同期が取れるか
- 文字中心でも視聴を続けられる画面設計になっているか
- 1話の生成に必要な手順と所要時間を測定できるか
- 動画を再生成したとき、同じ設定で再現できるか

### 成果物

- 読み上げ用原稿
- 音声ファイル
- 字幕ファイル
- 動画ファイル
- 素材・生成設定の記録
- 品質チェック結果と制作時間

## 7. 品質チェックリスト

- [ ] 原稿の主張・順序・意味が維持されている
- [ ] 誤読、読み飛ばし、音声の途切れがない
- [ ] 字幕の誤字、表示崩れ、同期ずれがない
- [ ] スマートフォン相当の画面サイズで文字が読める
- [ ] 音声がBGMに埋もれていない
- [ ] 画像・音楽・フォント等の利用条件を確認した
- [ ] 最初から最後まで再生でき、映像・音声が欠落していない
- [ ] 制作設定と所要時間を記録した

## 9. 記録する指標

| 分類 | 指標 |
|---|---|
| 制作 | 1話あたりの作業時間、生成成功率、再生成回数 |
| 品質 | 誤読数、字幕修正数、映像・音声の不具合数 |
| コスト | TTS・生成処理・素材の1話あたり費用 |
| 視聴 | 再生数、平均視聴時間、視聴維持率（公開先で取得可能な場合） |
| 改善 | 指摘事項、対応内容、次話で再利用する改善 |

視聴データが取れない段階では、推測値を埋めず「未計測」と記録する。

## 10. メタデータ拡張案

既存の `episodes.jsonl` は原稿メタデータとして維持する。動画制作の状態を追加する場合は、原稿情報と混ぜず、別の制作記録（例：`video-production.jsonl`）に分ける。

制作記録の候補項目：

- `episode`
- `status`（planned / script_ready / audio_ready / video_ready / reviewed / published）
- `script_path`
- `audio_path`
- `subtitle_path`
- `video_path`
- `template_version`
- `duration_seconds`
- `production_seconds`
- `quality_checks`
- `published_url`
- `updated_at`

実ファイルが生成されていない段階では、存在するかのようなパスや公開URLを記録しない。

## 11. 直近の実行順

1. 第25話の原稿を読み上げ用に確認する。
2. TTS音声を1本生成し、読みと速度を確認する。
3. 音声に同期した字幕を生成する。
4. タイトル・字幕・概念図を含む最小動画を作る。
5. 品質チェックと制作時間を記録し、テンプレートを確定する。
6. 確定後に残り30話へ展開する。


## 12. GitHub Actionsでの実行

ワークフロー: [Build episode video](.github/workflows/video-production.yml)

### 入力と素材

- 実行方法：GitHub の **Actions → Build episode video → Run workflow**
- `episode`：生成する話数（1〜31）
- `speaker`：VOICEVOXの話者・スタイルID（初期値 `3`）
- 画像：`assets/images/01.png` のように、話数を2桁にしたPNGを配置する。例：第2話は `assets/images/02.png`。
- 原稿：`episodes.jsonl` に記録されたMarkdownファイルを使用する。

### 出力

成功すると、Actionsの実行結果に成果物（Artifact）として以下が保存される。

- `episode-NN.mp4`：字幕焼き込み済み動画
- `episode-NN.wav`：VOICEVOX音声
- `episode-NN.srt`：字幕ファイル

成果物はActionsの実行画面からダウンロードする。リポジトリへ生成物を自動コミットせず、巨大な音声・動画ファイルをGit履歴に混ぜない。

### 制約・確認事項

- GitHub Actions上でVOICEVOX EngineのCPU版コンテナを起動するため、初回はコンテナ取得と音声生成に時間がかかる。
- 字幕のタイミングは各音声チャンクの長さから算出する。公開前に誤読・改行・同期を人が確認する。
- 話者IDはVOICEVOXの利用可能なスタイルに合わせて指定する。利用規約とクレジット表記も公開前に確認する。
- 現状は1枚の静止画に字幕を合成するMVP。動き・場面切り替え・公開自動化は次段階で追加する。
